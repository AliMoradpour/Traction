# روش کار و قواعد

## شاخه‌ها

| شاخه | کاربرد |
|---|---|
| `dev` | شاخهٔ کاری. همهٔ تغییرها اول اینجا می‌آیند. Render هم از همین شاخه deploy می‌کند |
| `main` | نسخهٔ بازبینی‌شده. فقط وقتی `dev` آماده و CI سبز است، ادغام می‌شود |

## کامیت‌ها

- هر بخش منطقی، یک کامیت جدا.
- پیام کامیت به سبک Conventional Commits و انگلیسی: `feat(mobile): ...`، `fix(api): ...`، `docs: ...`، `style(...)`، `refactor(...)`، `chore: ...`، `build(...)`، `ci: ...`
- بعد از هر بخش: `git push origin dev`

## قواعد کد

| موضوع | قاعده |
|---|---|
| منطق | محاسبات و prompts در سرور؛ صفحه‌ها فقط نمایش می‌دهند |
| تاریخ | فقط توابع `src/lib/dates.ts`؛ لحظهٔ مطلق محلی بفرستید، نه `YYYY-MM-DD` |
| رنگ و فاصله | فقط از `theme`؛ کد رنگ ثابت ننویسید |
| صفحهٔ جدید | از کیت `src/components/calm` (`Page`، `Card`، `Group`/`Row`، …) استفاده کنید |
| متن رابط | حروف عادی جمله، لحن مهربان، بدون ایموجی |
| داده | React Query (`src/hooks`) برای دادهٔ سرور؛ Zustand فقط برای وضعیت محلی |
| شکل پاسخ API | اگر شکل پاسخ سرور با نیاز اپ فرق دارد، در لایهٔ `services` تبدیل کنید |
| مهاجرت پایگاه داده | هر تغییر schema با یک مهاجرت (`prisma migrate dev`) |
| اسرار | هرگز در گیت؛ فقط در داشبورد Render، Neon و `.env` محلی |

## چک‌لیست ویژگی جدید

1. سرور: DTO، سرویس، کنترلر و در صورت نیاز مهاجرت.
2. اپ: مسیر در `src/api/endpoints.ts`، تابع در `src/services`، هوک در `src/hooks`، صفحه در `app/`.
3. تست برای منطق مهم.
4. بررسی‌های تایپ، lint و تست (فایل [testing-ci.md](testing-ci.md)).
5. بررسی در Expo Go روی آیفون، هم حالت روشن و هم تاریک.
6. به‌روزرسانی `CHANGELOG.md` و در صورت لزوم این مستندات.
7. کامیت و push به `dev`.
