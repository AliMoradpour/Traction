نسخهٔ ۱ · آبان ۱۴۰۵ (نوامبر ۲۰۲۶)

این راهنما چه کاری انجام می‌دهد؟

پس از انجام این راهنما، تِرَکشن بدون نیاز به روشن‌بودن لپ‌تاپ شما، از هر جایی روی آیفون (به صورت اپ نصب‌شده روی صفحهٔ اصلی) و اندروید کار می‌کند. همهٔ سرویس‌های این راهنما رایگان هستند.

بخشسرویسنقش
پایگاه دادهNeon (neon.tech)نگه‌داری همهٔ داده‌ها (PostgreSQL)
سرور APIRender، سرویس traction-apiاجرای کد backend/
وب‌اپRender، سرویس traction-appنسخهٔ وب اپ که روی آیفون نصب می‌شود
هوش مصنوعی (اختیاری)OpenRouter (openrouter.ai)قابلیت‌های هوشمند
پیش از شروع مخزن گیت‌هاب Traction باید خصوصی (Private) باشد. نشانی‌ها، رمزها و کلیدهایی که در این مراحل می‌گیرید را فقط در داشبورد همان سرویس‌ها بچسبانید؛ هرگز در گیت، چت یا ایمیل نفرستید.

مرحلهٔ ۱: پایگاه داده روی Neon (۵ دقیقه)

  1. به https://neon.tech بروید و وارد شوید (با گیت‌هاب یا ایمیل).
  2. یک پروژهٔ جدید بسازید. منطقه (Region) را Frankfurt انتخاب کنید (نزدیک به سرور Render).
  3. در داشبورد پروژه روی Connect بزنید، گزینهٔ Connection pooling را خاموش کنید و نشانی اتصال را کپی کنید. با postgresql:// شروع می‌شود.
  4. این نشانی همان DATABASE_URL است. آن را جایی امن نگه دارید و به کسی ندهید.

مرحلهٔ ۲: سرور و وب‌اپ روی Render (۱۰ دقیقه)

  1. به https://render.com بروید و با حساب گیت‌هاب وارد شوید.
  2. New → Blueprint را بزنید و مخزن Traction را انتخاب کنید. Render فایل render.yaml را می‌خواند و دو سرویس نشان می‌دهد: traction-api و traction-app. شاخه: dev.
  3. Render مقدارهای محرمانه را می‌پرسد:
    متغیرمقدار
    DATABASE_URLنشانی Neon از مرحلهٔ ۱
    OPENROUTER_API_KEYکلید شما از openrouter.ai/keys (برای قابلیت‌های هوشمند)؛ اگر ندارید فعلاً x
    CORS_ORIGINفعلاً x (در گام ۶ پر می‌شود)
    EXPO_PUBLIC_API_URLفعلاً x (در گام ۶ پر می‌شود)
    VAPID_PUBLIC_KEY و VAPID_PRIVATE_KEYx (برای یادآورهای آینده)
  4. Apply را بزنید و صبر کنید تا هر دو سرویس ساخته شوند (بار اول حدود ۵ تا ۱۰ دقیقه).
  5. دو نشانی که Render می‌دهد را کپی کنید، مثلاً https://traction-api-xxxx.onrender.com و https://traction-app-xxxx.onrender.com.
  6. جای خالی‌ها را پر کنید و هر سرویس را دوباره deploy کنید (Manual Deploy → Deploy latest commit):
    • traction-api → Environment → CORS_ORIGIN = نشانی app
    • traction-app → Environment → EXPO_PUBLIC_API_URL = نشانی api
بررسی نشانی <api>/api/health را در مرورگر باز کنید. باید {"status":"ok",...} ببینید.

مرحلهٔ ۳: نصب روی آیفون

  1. نشانی app را در Safari باز کنید و حساب بسازید.
  2. دکمهٔ Share (مربع با فلش) → Add to Home Screen را بزنید. حالا تِرَکشن را از صفحهٔ اصلی باز کنید.
  3. در Render، برای traction-api مقدار ALLOW_REGISTRATION را false کنید و دوباره deploy کنید تا کس دیگری نتواند در سرور شما حساب بسازد. (برای دعوت کاربران آزمایشی، فعلاً true بگذارید.)

مرحلهٔ ۴: اندروید (اختیاری)

ساخت ابری EAS فایل .env محلی را نمی‌بیند. نشانی سرور را در apps/mobile/eas.json زیر پروفایل preview بگذارید:

"preview": {
  "distribution": "internal",
  "env": { "EXPO_PUBLIC_API_URL": "https://traction-api-xxxx.onrender.com" }
}

سپس:

cd apps/mobile
npx eas-cli build -p android --profile preview

پیوند نصب APK را به گوشی‌های اندروید بفرستید.

به‌روزرسانی‌های بعدی

  • هر push به شاخهٔ dev هر دو سرویس را خودکار دوباره می‌سازد.
  • مهاجرت‌های پایگاه داده هنگام شروع سرور خودکار اجرا می‌شوند (npx prisma migrate deploy).
  • وضعیت ساخت و لاگ‌ها: داشبورد Render → سرویس → Logs.

نکته‌های مهم

  • خواب سرور رایگان: سرور رایگان Render پس از ۱۵ دقیقه بی‌کاری می‌خوابد. اولین باز کردن پس از استراحت ممکن است تا یک دقیقه طول بکشد؛ پس از آن سریع است.
  • داده‌ها: داده‌ها در Neon می‌مانند؛ سرور Render هیچ داده‌ای نگه نمی‌دارد.
  • پشتیبان: Neon امکان بازگشت به نقطه‌ای در گذشته را دارد (داشبورد Neon → Restore).
  • لو رفتن کلید: در همان سرویس کلید جدید بسازید، در Render جایگزین کنید و دوباره deploy کنید.
